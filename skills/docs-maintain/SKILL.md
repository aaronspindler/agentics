# Docs Maintain

1. Read [repository context](references/repository-context.md), resolve the requested docs boundary, and use an existing audit or targeted source comparison to identify concrete drift.
2. Update the canonical owner in place. Keep top-level routers concise; preserve distinct audience needs while removing contradictory duplicate guidance.
3. Trace operational instructions to their actual implementation, prerequisites, execution location, artifact source, and side effects. Describe absent automation as absent; do not change implementation to make stale prose true.
4. Keep product-specific depth with its owner and mutable inventory data in the canonical inventory. Preserve project policy for backlog, private operator material, public docs, and generated files.
5. Run appropriate docs/metadata validation and report changes with source evidence and remaining unknowns. Publishing or deploying requires its own existing authorization.
