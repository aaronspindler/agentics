# Backlog Maintain

1. Read [repository context](references/repository-context.md), discover the target project's backlog owner and issue templates, and resolve repository/project scope.
2. Search open, closed, and related issue families before writing. Reuse or refine existing issues before creating another; keep one concrete problem/outcome per issue.
3. Follow existing title/body templates and use project/issue fields and logical milestones for grouping. Do not invent labels where existing fields suffice.
4. Require evidence for each gap. Keep durable architecture/workflow docs distinct from issue-owned work queues when that is project policy.
5. Prepare exact proposed changes and perform only GitHub writes covered by current authorization. Report created, updated, reused, and skipped issues and any missing decisions.
